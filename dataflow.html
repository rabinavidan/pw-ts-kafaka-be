Step 01
Fixture Setup
Playwright injects a fresh ApiHelper per test via src/fixtures/index.ts. Base URL and auth headers are read from src/config/api.config.ts.
Step 02
Data Factory
src/utils/data.factory.ts builds randomised request payloads so each run is independent. The factory feeds directly into ApiHelper.
Step 03
HTTP Request →
ApiHelper sends the request to mock-server.js :3000 locally (or a real backend in CI). Retry logic and Winston logging wrap every call.
Step 04
← HTTP Response
mock-server.js returns JSON + status. The response travels back to ApiHelper, which records timing and surfaces it to the test.
Step 05
Response Typing
Raw JSON is cast to typed interfaces from src/models/api.model.ts — TypeScript flags contract drift at compile time, not at runtime.
Step 06
Assertion + Teardown
Helpers in src/utils/assertion.ts validate status, body shape, and SLA timing. Fixture afterEach flushes logs — no state leaks between tests.
Kafka Producer → Broker → Consumer Flow
How messages travel from test to topic and back
Produce
Consume
Dead-Letter
Topic Partitions (3 per topic)
Produce
KafkaHelper.produce()
Accepts a topic, key, value, and optional headers. Serialises to JSON, adds a trace-id header, sends via KafkaJS producer.
Partition
Key-based routing
KafkaJS hashes the message key to select a partition, guaranteeing ordering for messages with the same key (e.g. same orderId).
Consume
KafkaHelper.consume(filter)
A predicate function is passed — only messages matching the filter resolve the promise. This avoids offset coupling and test pollution.
DLQ
Dead-Letter Queue
Messages that fail processing are routed to dead-letter-queue. Tests assert DLQ receipt to verify error-path behaviour.

Gate 01
Lint & Type-check
ESLint with @typescript-eslint rules + tsc --noEmit strict mode. Zero errors required before any test job starts.
Gate 02
API Tests
Runs in parallel with Kafka tests. A MockServer Docker service container stands in for the real backend. Covers health, orders, payments.
Gate 03
Kafka Tests
Confluent Platform container is spun up. Topics are pre-created via a setup step. Producer, consumer, and message-flow specs run.
Gate 04
Integration Tests
needs: [test-api, test-kafka] — only runs if both pass. Tests the full API → Kafka → downstream chain in one job.
Gate 05
Publish Report
HTML report, results.json, and trace zips uploaded as artifacts (14-day retention). Markdown summary posted to step summary.
Always
Artifacts
Artifacts are uploaded even on failure so engineers can inspect traces and logs without re-running the failing suite locally.
